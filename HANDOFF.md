## 1. Что за проект

Музыкальное медиа (новости + релизы + ежедневный чарт Top 50). Стек:

- **Cloudflare Worker** (`worker.js`) + статика в `public/` (деплой: push в GitHub main → Cloudflare собирает сам)
- **KV namespace `DESK`** — посты (`desk`), чарт (`top50v6`), подписчики
- **Functions/Pages Functions** в `functions/api/` — desk.js, top50.js, preview.js, subscribe.js, broadcast.js, mail.js, subscribers.js
- **Кроп-воркер `scripts/serve.py`** — локальный сервер для превью (порт берёт из `PORT`, по умолчанию 43123; умеет проксировать `/apple-embed/us/album/<id>?i=<song>` — живой Apple-эмбед с инжектом фиксов)
- Репозиторий: `bohatykhvlad-bot/music98-news` (приватный), ветка `main`

Ключевые файлы фронта:
- `public/index.html` — весь сайт (одна страница + JS inline, ~2500 строк)
- `public/admin-desk.html` — админка
- `public/apple-player-fix.js` — инжект-скрипт в Apple-эмбеды
- `public/data/desk.json` — **seed-данные постов** (реальные посты живут в KV, прод через `/api/desk`)

Эмбеды (`/apple-embed/us/album/<id>?i=<song>`) проксируются воркером, в HTML инжектится `<script src="/apple-player-fix.js?v=editorial-NNN">`. **Версия `editorial-110`** — при любом изменении скрипта поднимать номер и в `worker.js`, и в `scripts/serve.py` (инжект-тег + cache-busting).

Что уже выучено (не наступи на те же грабли):
- Прыжок полосы в песенном плеере (initial→active свап, +4px) — **натив Apple**, победить без артефактов нельзя. Версии с пинами (editorial-106/107/108) давали дрожь/медленный плей. Откат — правильное решение (editorial-109/110).
- «Улёт вверх» плашки подписки при закрытии — натив: Apple схлопывает контейнер `:has(.audio-overlay--hidden){height:0}` при bottom-anchored модалке (прыжок 21→−46 за кадр). В editorial-110 сделан CSS-пин: `height:100% !important` + `pointer-events:none` скрытому состоянию — фейд на месте, клики сквозь проходят, проверено покадрово на живом эмбеде.
- Клик программно закрыть плашку нельзя (Stencil хранит состояние внутри) — не пытайся перехватывать закрытие.
- Пин координат/компенсации transform в эмбеде дают «дрожь» — Apple сам перестраивает layout, борьба с ним хуже бага.

Владелец прервал сессию на этом пункте. Три задачи, ничего из этого ещё не сделано:

### 4.1. Регресс: Apple-плеер на мобиле «включается-выключается»
После подвижек с громкостью (mkHoldZero/mkRamp в `public/apple-player-fix.js`) владелец reports: аудио в Apple-плеере на Android стартует и тут же останавливается, воспроизведение вообще нестабильно. Диагноз не проведён. Подозрительные места:
- `mkArm` ставит `mk.volume = 0` при хуке; `mkHoldZero` держит 0 через rAF 650мс (Android cold) / 260мс, потом `mkRamp`.
- Событие `playbackStateDidChange` → при переходе в playing вызывается `mkHoldZero` снова.
- **Гипотеза:** двойное удержание нуля + ramp конфликтуют с playbackState (Apple может ставить паузу при volume=0? — не проверено). Проверить на Android-устройстве/эмуляции: действительно ли причина в этом, или в чём-то ещё.
- Владелец хочет: **без взрыва громкости, минимальная задержка перед плеймом, и чтобы играло**. «На всех сайтах плеер играет нормально» — возможно, вообще отказаться от(volume-рампы) в MusicKit-пути и найти другой способ (например, только WebAudio на чарте, в эмбеде не трогать volume вообще).

### 4.2. Взрыв громкости в чарте НЕ ушёл
Несмотря на `volArm`/`gainZero`/`volRamp` в `public/index.html` (WebAudio gain-node, sample-accurate zero, dB-shaped ramp VOL_FADE_COLD=460мс), владелец говорит: взрыв в начале трека в чарте остался. Провести тесты с реальным устройством/эмуляцией Android:
- Путь: `armSrc` → `applySrc` → `tryPlay` → `volArm(warm)` ставит gain 0 сэмпл-точно → на `playing` событии `volPlaying()` → ramp.
- Возможные причины: (а) `attachOut()` создаёт AudioContext лениво, первый клик может пройти без gain (fallback `audio.muted=true` + 500ms wait — и там Android всё равно игнорирует volume первые ~500мс, отсюда взрыв); (б) blob vs stream — разные onset-пути; (в) событие `playing` приходит позже первого слышимого буфера.
- **Идея для проверки:** не unmute'ить пока `currentTime` < ~0.05s, форсировать suspend/resume AudioContext, или полностью перейти на Web Audio декодирование (decodeAudioData + BufferSource) вместо media element — там громкость сэмпл-точная гарантированно.

### 4.3. Тач-глич: при нажатии пальцем на трек в эмбеде плей-кнопка подпрыгивает на долю секунды
PC-вариант (удержание элемента) работает. На тач — не сделано. Попытка: ловить `touchstart`/`pointerdown` (type touch) на треках, применять те же стабилизаторы, что `onTrackGesture`. Если не выйдет — владелец принял ответ «плеер дефолтный» (ок). **Это низкий приоритет относительно звука.**

## 7. Стиль постов (для любого копирайтинга)

Зафиксировано в `site/_style-memory.md` (не удаляй, читай перед написанием постов):
- Текст поста пишется в момент публикации: можно today/just, если пост про свежее событие. Писать «обобщённо» (без today/just) — только отдельная просьба владельца под конкретный пост.
- Без двоеточий и точек с запятой, спокойный финал без афоризмов.
- Тизер 100–160 символов, без имени артиста (оно и так на карточке).
- Отсылки — только сверхузнаваемые (Beatles, Taylor Swift, Super Bowl); нишевые имена не брать, звучание описывать прямо.
- Фото: официальные пресс-материалы предпочтительны, но решается владельцем под конкретный пост (он сам ищет/выбирает фото).
- Посты пишутся СВОИМ текстом после выжимки из крупных изданий, не копипаст.
- Метки для YouTube-вставок: отдельной строкой `[YouTube — Song Title]`.

Разовые указания под конкретный пост (не общие правила!): капс-написание артиста (MILEY), отказ от today/just, требование именно пресс-релизных фото — всё это было только для поста MILEY «Bass Persuades». Для новых постов исходи из обычных правил выше, если владелец не скажет иное.

## 8. Как деплоить и проверять

1. Правки → `git add <files> && git commit -m "..." && git push` в `site/` (ветка main). Cloudflare сам пересоберёт (30-60с).
2. Проверка прода: `curl -s "https://music98.news/..."` — HTML уже с правкой? Инжект-версия поднята?
3. Локальный сервер: `python scripts/serve.py` (порт из `PORT`, дефолт 43123). В этом окружении фоновые процессы умирают при закрытии шелла — запускай detached (`subprocess.Popen` с `DETACHED_PROCESS`) и проверяй `curl`.
4. **Всегда проверяй правки на живом объекте, а не симуляцией** (урок сессии: «фикс» полосы проверяли на бумаге, а он не ловил правильный класс). Превью-инструменты: preview_navigate/preview_evaluate работают против локального сервера.
5. Каждое изменение в `public/apple-player-fix.js` → поднять `editorial-NNN` в `worker.js` И `scripts/serve.py`.
