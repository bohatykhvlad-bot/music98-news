# Рассылка music98.news — анализ вариантов и план реализации

Задача: **1 имейл в неделю**, визуальный (картинки + вёрстка внутри письма): топ-10 чарта с изменениями, 2 новости + 1 релиз короткой выжимкой. Отправка из админки (уже есть кнопка), позже — автоматизация по пятницам.

---

## 1. Что уже есть на сайте (важно — половина работы сделана)

В Cloudflare Worker уже реализовано:
- `/api/subscribe` — форма на сайте собирает почты
- `/api/subscribers` — список подписчиков
- `/api/broadcast` — **отправка через Resend уже вшита в код** (по одному письму на адрес, с ключом из настроек)
- `/api/mail` — настройка Resend-ключа и адреса отправителя прямо из админки
- В админке есть форма «Mail»: subject + текст → «Send to the list»

Чего не хватает: (а) красивый HTML-шаблон с картинками и вёрсткой (сейчас текст уезжает голым `<pre>`), (б) автосборка контента из постов и чарта, (в) расписание.

---

## 2. Миф про «купить почту и слать с неё»

**Именную почту (hello@music98.news) купить можно и нужно — но слать рассылку с неё напрямую НЕЛЬЗЯ.**

Почему: обычные почтовые ящики (Gmail, Zoho и т.д.) не предназначены для массовых писем. Пара сотен писем в день с такого ящика = мгновенный бан/спам-фильтр. У них нет инструментов: отписки, статистики открытий, репутации домена, batch-отправки.

Правильная архитектура (так делают все медиа):
- **Домен + именная почта** — для «лица»: replies, ответов читателям
- **Email-сервис (Resend и т.п.)** — для самой отправки, с проверкой домена
- Домен проходит SPF/DKIM/DMARC-верификацию у сервиса → письма подписаны твоим доменом → инбокс

## 4. Что нужно докупить/настроить (чеклист)

| Шаг | Что делать | Цена |
|---|---|---|
| 1 | Аккаунт на resend.com → Domains → добавить `music98.news` | $0 |
| 2 | Добавить DNS-записи (Resend покажет какие): SPF, DKIM, DMARC, кастомный Return-Path | $0 |
| 3 | Именная почта: Zoho Mail Lite ($1/мес) или Google Workspace ($7/мес) → `hello@music98.news` для replies | $1–7/мес |
| 4 | В админке: Mail → вписать Resend API key + `news@music98.news` как from | $0 |
| 5 | Warm-up: первые 2-3 недели слать маленькими порциями (список маленький — само сработает) | — |

Gmail/Outlook с 2024 требуют обязательных SPF+DKIM+DMARC для всех булк-отправителей — Resend это закрывает автоматически после верификации домена.

## 5. Как собрать само письмо (топ-10 чарта + 2 новости + 1 релиз)

### Вариант A — Recommended: шаблон в коде + автосборка из desk.json
1. В воркер добавляем функцию `buildWeeklyEmail(desk, chart)` — собирает HTML-шаблон:
   - Шапка: логотип + «music98.news Weekly»
   - **Top 10 чарта** — таблица с позициями, стрелками изменений (▲▼—), обложками (60×60), превью-плеер не нужен (в письмах не работает) — ссылки на чарт
   - **2 новости**: картинка + заголовок + тизер 2 строки + кнопка «Read»
   - **1 релиз**: обложка + Artist — Title + 1-2 предложения + Apple-ссылка
   - Футер: unsubscribe-ссылка (обязательно по закону)
2. Стили только инлайн (Gmail вырезает `<style>`) — таблицы вместо flexbox (email-вёрстка = 2005)
3. Картинки — ссылки на твой прод (`https://music98.news/photos/...`), они уже в KV
4. Отправка: та же `/api/broadcast`, но с собранным HTML вместо `<pre>`
5. В админке: кнопка «Preview email» → открывает собранный HTML в новом окне → «Send»
6. Позже: Cloudflare Cron Trigger (пятница 09:00 UTC) — worker сам собирает и шлёт

**Плюсы:** полный контроль, вписывается в текущий дизайн (циан, стекло, шрифты сайта), $0. **Минусы:** шаблон надо один раз написать (~1 день работы).

### Вариант B — Brevo вместо Resend, шаблон в их билдере
Перенести отправку на Brevo API, шаблон собрать в их drag&drop билдере, из кода — только подстановка данных в плейсхолдеры.
**Плюсы:** шаблон красивый без ручной вёрстки. **Минусы:** переносить код, билдер всё равно требует подстановку контента API-вызовом, лимит 300/день упирается быстро.

### Вариант C — Mailchimp полностью
Весь флоу в Mailchimp, с сайта только сбор подписчиков через их форму.
**Плюсы:** самый мощный билдер. **Минусы:** дорого при росте, сторонний бренд в письмах, разрыв с текущей админкой.

### Рекомендация: **A** (Resend + свой шаблон + cron)

## 6. Архитектура решения (после согласования)

```
[Пятница 09:00 UTC — Cron Trigger]
        ↓
Worker: читает desk.json (посты) + top50
        ↓
buildWeeklyEmail(): HTML с инлайн-стилями
  ├─ Top 10 (позиции, стрелки, обложки)
  ├─ 2 новости (обложка+заголовок+тизер+кнопка)
  ├─ 1 релиз (обложка+артист+выжимка+Apple-ссылка)
  └─ unsubscribe-ссылка (подпись HMAC, одноразовая)
        ↓
Resend API: рассылка всем подписчикам (batch, по одному на адрес)
        ↓
Статистика: deliveries/opens — Resend webhook → KV
```

Ручной режим (пока без cron): в админке кнопка «Send weekly email» — собирает из текущих данных и шлёт сразу, с preview перед отправкой.
