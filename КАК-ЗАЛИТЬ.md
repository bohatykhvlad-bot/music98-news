# Как залить music98.news (по шагам)

Делаем по одному пункту. Написал «готово» — идём дальше.

## Зачем это нужно

Есть **два** автообновления чарта. Они не мешают друг другу.

1. **Первый заход за день** — сайт сам дергает `/api/top50` и пересобирает список. Для этого сайт должен быть на **Cloudflare Pages** (не просто «файлы на диске»).
2. **Ночной скрипт** — GitHub раз в сутки перезаписывает `data/top50.json` и Pages заново публикует сайт. Для этого репозиторий должен жить на **GitHub** и быть подключён к Pages.

Админка и подписка отдельно: им нужно хранилище KV. К чарту это не обязательно. KV подключим после того, как сайт откроется.

## Шаг 1. Репозиторий на GitHub

1. Зайди на [github.com](https://github.com) и войди (или зарегистрируйся).
2. **New repository**. Имя, например `music98-news`. Private или Public — как удобно.
3. **Не** ставь галочки README / .gitignore — папка у нас уже есть.
4. Напиши сюда ссылку вида `https://github.com/твой-логин/music98-news`.

Дальше я скажу, как залить файлы (через сайт GitHub или через команду).

## Шаг 2. Cloudflare Pages из GitHub

1. Зайди на [dash.cloudflare.com](https://dash.cloudflare.com).
2. **Workers & Pages** → **Create** → **Pages** → **Connect to Git**.
3. Разрешить Cloudflare доступ к GitHub, выбрать репозиторий `music98-news`.
4. Настройки сборки:
   - Framework preset: **None**
   - Build command: **пусто**
   - Output directory: `/` или оставить пустым (корень)
5. **Save and Deploy**.

Когда появится адрес вида `https://что-то.pages.dev` — пришли его.

## Шаг 3. Проверить чарт

Открой `https://твой-сайт.pages.dev` → Charts. Должно быть «Updated today» или «This week’s Top 50».  
Открой `https://твой-сайт.pages.dev/api/top50` — должен прийти JSON с 50 треками.

Это и есть «первый заход за день».

## Шаг 4. Ночной скрипт (уже лежит в проекте)

Файл `.github/workflows/daily-top50.yml` уже есть. Когда репозиторий на GitHub:

1. GitHub → твой репозиторий → **Settings** → **Actions** → **General** → разрешить Actions.
2. **Actions** → **Daily Top 50** → **Run workflow** (проверка вручную).
3. Расписание уже стоит: каждый день 07:00 UTC.

Чтобы Action мог коммитить файл обратно, у репозитория должны быть права **Read and write** для Workflows (Settings → Actions → General → Workflow permissions).

## Шаг 5. Потом (не сейчас)

- KV с именем `DESK` — чтобы админка и подписка писали на сервер.
- Переменная `ADMIN_PASSWORD`.
- Resend — когда будем слать письма.

Пароль админки и письма **не** нужны, чтобы чарт обновлялся.
