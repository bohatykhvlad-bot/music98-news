# Сайт на Netlify (если он у тебя уже там)

Сайт снова обычная папка с HTML. Папка `functions/` — это для Cloudflare, Netlify её больше не должен трогать.

1. Открой [https://app.netlify.com](https://app.netlify.com) и свой сайт.
2. **Site configuration** (шестерёнка) → **Build & deploy** → **Build settings** → **Configure**:
   - Build command — **пусто**
   - Publish directory — **пусто** или точка `.`
   - Functions directory — `netlify/functions` (не `functions`)
3. Save.
4. **Deploys** → если последний красный, **Retry**. Если заливал zip/папку — **Deploys** → перетащи **новую** папку проекта (или архив `music98-netlify.zip`) в область «Need to update your site? Drag and drop».
5. Открой ссылку вида `https://что-то.netlify.app` в новой вкладке Chrome (не в Git).

Чарт и новости откроются. Редактор (`/m98desk.html`) на Netlify текст покажет, но Publish в облако без KV Cloudflare не запишет — это нормально.

# Как залить music98.news на Cloudflare

Делай по пунктам сверху вниз. Если застрял — напиши номер шага и что видишь на экране.

Не заливай zip и не жми Direct Upload / Upload assets: так сайт откроется картинкой, но редактор, подписка и живой чарт не заработают. Нужен **Cloudflare Pages + GitHub**.

---

## Шаг 1. Аккаунт Cloudflare

Открой эту ссылку:

**https://dash.cloudflare.com/sign-up**

Если аккаунт уже есть:

**https://dash.cloudflare.com/login**

После входа должна открыться панель. Слева ищи **Workers & Pages** (иногда **Compute**). Прямая ссылка после входа:

**https://dash.cloudflare.com/?to=/:account/workers-and-pages**

Напиши «шаг 1 готов», когда видишь эту страницу.

---

## Шаг 2. Репозиторий на GitHub

Cloudflare умеет забирать код только с GitHub или GitLab. Сейчас проект живёт здесь, в Cursor — его нужно один раз выложить на GitHub.

Самый простой путь в этом чате: нажми **Create repo** (таблетка сверху). Имя, например `music98-news`. Можно Private.

Или вручную:

1. Открой **https://github.com/new**
2. Имя: `music98-news`
3. Private или Public — как удобно
4. **Не** ставь галочки README / .gitignore / license — файлы уже есть
5. Create repository

Когда появится страница репозитория, пришли ссылку вида `https://github.com/твой-логин/music98-news`.

---

## Шаг 3. Сайт на Cloudflare Pages

1. Открой **https://dash.cloudflare.com/?to=/:account/workers-and-pages**
2. **Create** (или **Create application**)
3. **Pages** → **Connect to Git**
4. **GitHub** → разреши доступ (Authorize / Install & Authorize)
5. Выбери репозиторий `music98-news` → **Begin setup**

Настройки сборки — скопируй один в один:

| Поле | Что поставить |
|---|---|
| Project name | `music98-news` (или любое, это будет `имя.pages.dev`) |
| Production branch | `main` |
| Framework preset | **None** |
| Build command | **пусто** (ничего не пиши) |
| Build output directory | `/` или оставь пустым |

6. **Save and Deploy**

Подожди 1–2 минуты, пока статус станет Success. Появится адрес:

`https://music98-news.pages.dev`  
(имя может быть другим, если занято)

Открой его — это уже публичный сайт. Пришли эту ссылку.

Редактор (не светится в меню, запомни сам):  
`https://ТВОЙ-САЙТ.pages.dev/m98desk.html`  
Пароль пока: `music98`

---

## Шаг 4. Тетрадка KV (чтобы статьи и почта сохранялись)

Без этого шага сайт открывается, чарт может жить на запечённом файле, но **Publish в редакторе** и **Subscribe** не запишутся.

### 4a. Создать хранилище

1. **https://dash.cloudflare.com/?to=/:account/workers/kv/namespaces**
2. **Create namespace** (или **Create**)
3. Имя: `music98-desk`
4. Create / Add

Это просто коробка. Имя коробки любое. Важно следующее.

### 4b. Привязать к сайту как `DESK`

1. Снова **https://dash.cloudflare.com/?to=/:account/workers-and-pages**
2. Кликни проект **music98-news**
3. **Settings**
4. **Bindings** → **Add** → **KV namespace**
5. **Variable name** — напиши ровно: `DESK`  
   (заглавными. Не `desk`, не `KV`, не `music98-desk`)
6. **KV namespace** — выбери `music98-desk`
7. Save

### 4c. Пересобрать

Bindings включаются после нового деплоя:

1. В проекте вкладка **Deployments**
2. Последний деплой → **⋯** → **Retry deployment**  
   или **Retry** на зелёном билде

---

## Шаг 5. Пароль редактора

1. Тот же проект → **Settings**
2. **Variables and Secrets** → **Add**
3. Name: `ADMIN_PASSWORD`
4. Value: свой пароль (не оставляй `music98` навсегда)
5. Включи **Encrypt** / тип **Secret**
6. Save
7. Снова **Retry deployment**

После этого входи в `/m98desk.html` уже новым паролем.

Письма рассылки — потом. Когда дойдём, добавим `RESEND_API_KEY` и `FROM_EMAIL` так же, как пароль.

---

## Шаг 6. Проверка

Открой:

1. `https://ТВОЙ-САЙТ.pages.dev` — главная
2. `https://ТВОЙ-САЙТ.pages.dev/api/top50` — должен быть JSON с `"tracks"`
3. `https://ТВОЙ-САЙТ.pages.dev/m98desk.html` — пароль → Publish одной тестовой новости → обнови главную

Если пункт 3 пишет ошибку про KV — вернись к шагу 4: Variable name должен быть `DESK`, и после привязки нужен Retry deployment.

## Что не нажимать

- **Direct Upload** / **Upload assets** / zip — сайт без редактора и без живого `/api`
- **R2** — это диск для файлов, не сайт
- **Workers** отдельно, руками — не нужно: папка `functions/` уже становится API, когда проект Pages подключён к Git
- Кнопку **Publish** в Cursor — это Vercel, не Cloudflare. Для Cloudflare идём только по этой инструкции
